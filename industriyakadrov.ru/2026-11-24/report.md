## 1. Главное

С августа на сайте сделана большая работа: исправлена страница с ошибкой 500, убраны двойные `<h1>` и слипшиеся описания, у всех вакансий есть `validThrough`, глубина вложенности упала с 14 кликов до 3–4, появились страницы профессий (`/vacancy/gornichnaya/` и ещё 15) и раздел статей. **Из 26 находок августа закрыто 12, частично или с оговоркой — 7, не сделано — 7.**

Главная проблема сейчас новая: **Яндекс держит в поиске 584 адреса сайта, и 495 из них (85 %) отдают 404.** Это старые карточки вакансий (456) и страницы пагинации (39), удалённые без перенаправлений. Люди из поиска уже попадают на «Страница не найдена»: только за 1–23 ноября — 8 визитов из органики. Вторая проблема осталась с августа: **через 10 секунд на любой странице открывается окно заявки на весь экран** — на мобильном оно закрывает страницу целиком и само становится «главным элементом» для метрики скорости LCP (14–19 с вместо 3–4 с).

Трафик из поиска растёт: **ноябрь (1–23) — 135 визитов из поисковиков против 120 за весь октябрь**, по неделям органика выросла с 25–29 до 37–50 визитов. Но небрендовый спрос почти не конвертируется в клики: по коммерческим запросам («кадровый аутсорсинг спб», «услуги аутсорсинга персонала») сайт показывается на 7–14 месте и **кликов 0**; 88 % органических входов в октябре — на главную по брендовым запросам.

**Что делать первым:** 301-перенаправления с 495 мёртвых адресов на страницы профессий (готовая карта приложена), убрать или смягчить окно-таймер, починить 4 битые ссылки в статьях.

## 4. Критичные проблемы (🔥)

### 🔥1. 495 адресов в поиске Яндекса отдают 404

- **Что не так.** Вебмастер показывает 584 адреса в поиске. Каждый проверен запросом 24.11: **495 → 404**, 7 → 301, 82 → 200. Среди 404: **456 старых карточек** `/vacancy/id/*` и **39 страниц пагинации** `/vacancy/page/4/` и дальше. В sitemap сейчас 70 вакансий вместо 458 в августе: закрытые вакансии удалили, а перенаправления не поставили.
- **Почему это бьёт по трафику.** Люди из поиска попадают на «Страница не найдена» — в ноябре это видно в Метрике: из органики вошли на `/vacancy/id/2317/` (5 визитов), `/vacancy/id/2267/` (2), `/vacancy/id/1874/` (1), все отдают 404. Накопленный вес этих страниц теряется. Яндекс постепенно выбросит их сам, но не перенесёт ценность на живые страницы. Последний раз робот заходил на большинство из них в августе (362 из 584), поэтому чистка займёт месяцы.
- **Как чинить.** 301 с каждой закрытой вакансии на страницу её профессии. **Готовая карта на 491 адрес приложена:** [redirect-map-404.csv](redirect-map-404.csv), профессия определена по заголовку страницы в Яндексе. 350 адресов сопоставлены со страницей профессии (горничная — 204, подсобный рабочий — 35, уборщик — 25, мойщик — 20…), 141 — на `/vacancy/` (профессии без своей страницы и пагинация). На будущее: при закрытии вакансии автоматически ставить 301 на страницу профессии, а не удалять запись. Если страницы профессии нет — отдавать 410.
- **Трудоёмкость:** 2–4 часа (плагин Redirection или правила nginx по CSV) + правило автоматического редиректа — 0,5–1 день.

### 🔥2. Окно заявки на весь экран через 10 секунд

- **Что не так.** На всех проверенных страницах (главная, услуги, вакансии, статьи, контакты) через ~10 с открывается `#modal_form_timer` «Не нашли что искали?» с затемнением. На мобильном одновременно видны окно, плашка cookie и кнопка чата — страница закрыта полностью (кадр ниже).
- **Почему бьёт.** Яндекс и Google понижают страницы с навязчивыми перекрывающими окнами на мобильных. Окно ещё и портит метрику скорости: замер на профиле «медленный 4G + CPU ×4» показал, что основной контент отрисовывается за **2,9–3,9 с**, но через 14–15 с самым крупным элементом становится окно, и итоговый LCP — **14–19 с**. Человек, который читает вакансию, теряет её из виду ради формы.
- **Как чинить.** Убрать таймер на мобильных совсем. На десктопе — показывать при намерении уйти (курсор к закрытию вкладки) не чаще раза за сессию и не на карточках вакансий. Как альтернатива — компактная плашка внизу экрана, а не окно на весь экран.
- **Трудоёмкость:** 1–2 часа.

## 10. Что проверить не удалось

- **Google Search Console** — доступа нет: в файлах проекта лежат только ключи API Яндекс.Метрики и Вебмастера. Данные по Google взяты только из Метрики (45–51 визит в месяц).
- **Детализация запросов Вебмастера за ноябрь** — отчёт «популярные запросы» за ноябрь пока пустой (данные в Вебмастере приходят с задержкой), поэтому разбивка по запросам дана за сентябрь, а итоги ноября — по общей истории всех запросов.
- **Полевые Core Web Vitals (CrUX)** не использовались; скорость измерена в браузере Chromium на двух профилях (см. «Методика»).

## Методика

- **Обход сайта:** 165 адресов (118 из sitemap + найденные по внутренним ссылкам), коды ответов без следования редиректам, разбор title, description, H1, canonical, meta robots, JSON-LD, картинок и ссылок. Глубина — обход в ширину от главной.
- **Индекс:** все 584 адреса из отчёта Вебмастера «Страницы в поиске» проверены запросом GET 24.11.2026.
- **Скорость:** Chromium без интерфейса. Мобильный профиль — iPhone 390×844, сеть 1,6 Мбит/с с задержкой 150 мс, процессор ×4; десктоп — 1440×900 без ограничений. Девять страниц, LCP/CLS/FCP — через PerformanceObserver.
- **Данные:** API Яндекс.Метрики (счётчик 105287146) и Яндекс.Вебмастера, периоды — июль–ноябрь 2026.
